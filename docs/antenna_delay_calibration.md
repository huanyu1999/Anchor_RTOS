# UWB 天线延时（ANT_DLY）标定指南

> 适用：本项目 DW1000 / DW3000 双基站 + 标签 TWR 测距系统
> 关联代码：`01_Core/App/Inc/dw_instance.h`（`ANT_DLY`）、`01_Core/App/Src/dw_main.c`（`dwt_set{rx,tx}antennadelay`）、`01_Core/App/Src/dw_instance_anchor.c`（TOF 计算）

---

## 1. 它解决什么问题

天线延时补偿的是：信号在“数字打时间戳的点 ↔ 天线参考面”之间走线/电路引入的固定时延。不补偿，测距结果会有一个**与距离无关的固定偏移**。

判别方向（见 `dw_instance.h` 注释）：

| 现象 | 含义 | 操作 |
|---|---|---|
| 计算距离 **比实际大** | 天线延时设小了 | **增大** `ANT_DLY` |
| 计算距离 **比实际小 / 出负数** | 天线延时设大了 | **减小** `ANT_DLY` |

---

## 2. 核心原理：误差属于「一对」，不属于单个设备

TWR 距离误差由**这一对设备（标签 + 该基站）天线延时之和**决定。对本项目的非对称 DS-TWR 公式严格推导：

```
计算 tof = 真实 tof − (a_标签 + a_基站)        // 单位：DTU
```

推导要点（设 TX/RX 都用同一个 ant 值，本代码即如此）：
- 收发时间戳分别被天线延时拉早/拉晚，使两个“往返区间”各减 `2a`、两个“回复区间”各加 `2a`；
- 公式分母 `Ra+Rb+Da+Db` 中 `±2a` 正好抵消 → **分母不变**；
- 分子净减 `2a·(分母)` → `tof = tof_raw − 2a`（单设备等值时）；
- 标签、基站各自带延时时，结果只取决于二者之和 `a_标签 + a_基站`。

> **结论：单次 tag↔anchor 测距只能观测到「两端天线延时之和」，无法分离各自分量。** 那 60cm 误差是“这一对”的总误差，不是基站单独的。

---

## 3. 换算关系（DTU ↔ 距离）

- 1 个 `ANT_DLY` 单位 = 1 DTU ≈ **15.65 ps**
- 因 `tof = tof_raw − 2a`，距离对 `ANT_DLY` 的灵敏度：

```
Δ距离 = 2 × 15.65 ps × c ≈ 9.4 mm / 单位
```

**速算：每改 ±1 个 `ANT_DLY`，计算距离约变 ∓9.4 mm。**

实例：实测 0.95 m、计算 1.5 m（偏大 0.55~0.60 m）
```
0.60 m ÷ 9.4 mm/单位 ≈ 64 单位
ANT_DLY: 16485 → 16549   （已应用）
```

---

## 4. 标定流程

1. **固定一个已知距离**（建议别太近，例如 2~3 m，近距离接收易饱和、jitter 大）。
2. 连测一批，**看中位数 / 众数，不要看单个样本**（单样本含噪声尾巴）。
3. 按 §3 速算调 `ANT_DLY`，一次到位后再微调（线性关系）。
4. **必须在 2~3 个距离各验证一次**（如 0.95 m / 3 m / 5 m）：
   - 误差 **恒定**（不随距离变）→ 就是天线延时，按上面调即可；
   - 误差 **随距离放大** → 不是天线延时，是时钟/晶振或 `DWT_TIME_UNITS`/`SPEED_OF_LIGHT` 标度问题，调 `ANT_DLY` 会顾此失彼，需换思路。

## 5. 多基站 / 多标签的标定架构

### 原则：误差只在「一处」补一次

补偿压在标签还是基站都行，只要**每一对的和**对。本项目把整段误差**压在基站侧**。

> ⚠️ **同一处误差不要两边都补**。若基站调了 60cm，标签又为同样的 60cm 调一遍 → 重复补偿、过冲 ~60cm → 负值暴增。

### 多基站：每个基站对**同一参考标签各自校**

- 每个「基站-标签」是**独立的一对**。
- 同批 PCB、同 RF 配置 → 真实延时接近，可**先都设同一起点值**（如 16549）。
- 板间天线/走线/芯片差异有 ±几 cm~几十 cm，所以**每块基站都用同一个参考标签各自测**，偏的单独微调（各板可不同值）。
- 目标不是“所有基站数值相同”，而是“每块基站 + 那个标签 = 准”。

### 多标签：所有标签**必须统一**一个值

- 基站是“针对某个标签的天线延时”标定的；换上延时不同的标签，所有基站会整体偏，偏移量 = 标签间延时差。
- 同型号标签 HW 一致 → **全系统标签用同一个值**。
- 若某只标签明显偏，说明它的天线延时与别的不同，需单独校该标签或统一到同一值。

### 一句话总结

> **选一边（基站）承载校准 → 该边按每块板各自精校；另一边（标签）全系统统一一个值、保持不动。误差只在一处补一次。**

## 6. 关于「负值距离」

### 现象与本质

调大 `ANT_DLY` 后负值概率上升，是**诊断信号**，不是 `ANT_DLY` 把距离“弄负”了：

- 天线延时是**确定性常数**，**只平移均值，不改变离散度（jitter）**。
- 加 `ANT_DLY` = 整条分布下移；原本就存在的**低值噪声尾巴**越过 0 → 负值变多。
- 负值多 ⇒ 这批测量 **jitter 大**（近距离尤甚）。均值 ~0.9 m、σ~0.5 m 时约 1.8σ 过零，几个百分点负值率，与“明显增多”吻合。

### 处理原则

1. **不要为了消负值而回调 `ANT_DLY`**。那等于人为把距离往大偏 —— 对报警设备**危险**：远报近、临界**晚报警**。安全设备宁可准、不可偏大。
2. **标定看中位数**：中位数落在真值即标定到位，负值只是尾巴。
3. **负值的真正危害在软件层，必须加闸门**：
   - `tag_hashNode_t.distance` 是有符号 `int32_t`（`dw_sort.h`），最小堆比较 `node_less` 用有符号 `<`（`dw_sort.c`）→ **任何一个负值会冒到堆顶** → `disManager_getMin` 返回负值 → 喂给报警状态机 → 负值 `< ALARM_DIST_DANGER(10000)` → **误触发 L3 + 蜂鸣器**。
   - 现有唯一过滤 `if(distance_now_m > 20000.0) distance_now_m = -1;`（`dw_instance_anchor.c`）窗口 `(−∞, 20km]` 几乎不过滤，且把 `-1` 当“过远”哨兵却仍入队（`*1000 = -1000`）→ 哨兵自身污染堆。
   - `dw_instance_anchor.c` 中那段 tof 溢出处理是**死代码**（`tof` 是 double，三行互相覆盖，不起作用）。
   - **建议**：入队前做合法区间校验 `[DIST_MIN, DIST_MAX]`，越界（含负数）→ `range_status = RANGE_ERROR` 且**不入队**，并删掉死的 tof clamp。两版（DW1000/DW3000）通用。

### jitter 要不要压

- 现场报警门限 10~50 m，均值远离 0，**不会出负数**，jitter 占比小 → 台架近距离的负值多为噪声尾巴，加软件闸门即可。
- 若确需压 jitter：质量门控 `check_twr_quality` / NLOS（`dw_instance_anchor.c` 中目前 **DW1000-only**，DW3000 未接），或 `Com/` 下的 kalman 滤波。
